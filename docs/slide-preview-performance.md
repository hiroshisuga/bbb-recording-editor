# スライドプレビューの差分更新

通常再生で過去の描画イベントを再実行し、Tldrawの全図形を削除・作成していた処理を、イベントの差分反映へ変更した。

- `slideTimeline.js` がスライド関連イベントを一度だけ抽出し、時刻の二分探索と再生カーソルで新しく通過したイベントだけを処理する。同時刻は元の配列順を維持する。サーバーからの時刻順のイベント配列を前提とする。
- チャット、参加者情報などのイベントは対象外。非表示ページの変更も内部に保持し、表示中の図形は更新しない。カメラ変更はカメラだけに反映する。
- Tldrawでは変更された図形だけを更新し、同一トランザクションにまとめる。背景のアセットと図形は再利用する。ロックされた図形の削除と、不正な図形の隔離も扱う。
- 図形の部分更新は従来の再帰マージを維持する。シークでプロパティが消える場合は、その図形だけを再作成し、後の時刻の値を残さない。再生用のTldraw操作履歴は保持しない。
- 500個の関連イベントごとに最大16個の途中状態を保存する。ページのMapは変更時にコピーし、変更されていない図形オブジェクトは共有する。後方・大幅な前方シークでは、目的位置以前で最も近い保存状態か、利用可能な現在位置から復元する。保持範囲外の古い位置は先頭から復元するため、全シークの一定時間内完了を保証するものではない。イベント配列の差し替え時にはカーソルとキャッシュを破棄する。
- Reactの再生カーソル更新はコミット後のレイアウトエフェクトで行う。中断されたレンダーでは状態を変更しない。

## Chromiumでの比較

比較元は `6f76c3255d8360595f0abe301a6b3ff91741d535`。Linuxのheadless Chromium 156.0.8078.79、Intel Xeon Platinum 8573Cで、同じハーネス内の旧・新コンポーネントを別ページで実行した。実際のReactとTldrawキャンバスを使用する。

表示図形は100個。1万／5万回の合成図形イベントを持つ録画の終盤で、1イベントずつ進めた。初期化と4回のウォームアップ後の16回について、`flushSync` による同期更新の所要時間を測定した。各更新の間にアニメーションフレームを待ち、最後にチャットイベント通過時の図形操作と、後方・前方シーク後の図形数を確認した。

| 合成図形イベント数 | 旧：中央値 | 新：中央値 | 旧：最大 | 新：最大 |
| --- | ---: | ---: | ---: | ---: |
| 10,000 | 126.1 ms | 4.7 ms | 182.2 ms | 7.6 ms |
| 50,000 | 149.4 ms | 4.2 ms | 213.5 ms | 8.7 ms |

16回の更新で旧処理は図形削除APIを16回、図形作成APIを1,616回呼んだ。新処理は図形更新APIを16回呼び、再作成は0回だった。チャット通過時も旧処理は削除1回・作成101回、新処理は図形操作0回だった。API回数は背景を含む。

これはスライド更新の比較であり、初回読み込み、ブラウザの描画完了時間、映像デコード、音声処理、BBBサーバーや実録画の測定ではない。測定用バンドルはproductionモード・圧縮なし。外部アセット取得の影響を除くため、図形のみのフィクスチャとローカルのシステムフォント・翻訳応答を使用する。端末や録画内容による改善率を保証しない。

測定値は [slide-preview-results.json](slide-preview-results.json) に保存した。

## 再現

アプリの既存開発依存に加え、別途PlaywrightとChromiumが必要。アプリの依存関係への追加は不要。

```bash
node scripts/benchmark-slide-preview.cjs \
  --before 6f76c3255d8360595f0abe301a6b3ff91741d535 \
  --browser /usr/bin/chromium \
  --playwright /path/to/playwright \
  --output work/slide-preview-results.json
```

Linuxの `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` を使用する。ベンチマークはリポジトリの `work/` に一時バンドルを作成して終了時に削除し、ローカルHTTPサーバーを終了する。出力JSONは指定した場所に残す。

## 正確性の検証

従来の `slideState` と、前進・後退・同時刻・複数ページ・図形の部分更新・削除・全消去・チェックポイント退避を含む固定および疑似乱数のシーク列を比較する。キャッシュの上限、過去状態の不変性、処理イベント数も検査する。

Tldraw実エンジンのコンポーネントテストでは、無関係なイベントとカメラ変更時の不要な図形操作、未変更図形の保持、シークによるプロパティの巻き戻し、ロックされた図形、矢印の座標、不正な更新、資料のないページ、録画差し替え、StrictMode、従来のカメラ・ホイール操作制限を確認する。

全体のJavaScriptテストは22スイート・327件が通過し、Node.js 22での本番ビルドも成功した。

```bash
CI=true npm test -- --watchAll=false --runInBand
npm run build
```
